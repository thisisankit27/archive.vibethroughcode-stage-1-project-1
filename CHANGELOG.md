# Changelog

This project was built as a sequence of pull requests, each introducing exactly one engineering
concept. There are no released versions — the unit of change is a PR, so that is what this file
records.

Full reasoning for each decision, including the alternatives rejected, is in
[`docs/engineering-mindset/`](docs/engineering-mindset/).

---

## Week 4 — Production Readiness

Turning a prototype into an application: how long the user waits, what it remembers, what is
tunable, what happens when a dependency dies.

### PR-16 — Documentation
- Rewrote `README.md` as a description of what exists rather than a plan, including a **Known
  limitations** section stating each accepted trade-off and its reason.
- Added `LICENSE`, `CONTRIBUTING.md`, `SECURITY.md`, `CODE_OF_CONDUCT.md`, this file.
- Untracked `storage/` and added it to `.gitignore`. Runtime state — indexes, catalog, logs —
  had been committed since PR-9.
- **Not deployed**, deliberately. Deployment needs decisions this project has not made:
  where the index lives on an ephemeral filesystem, Ollama reachability, session state across
  replicas.

### PR-15 — Reliability Engineering
- `resilience.py`: retry classification, exponential backoff with full jitter, and
  `DependencyError` so infrastructure exceptions never reach the domain layer.
- A failure must be **transient *and* idempotent** to be retried. A 404 for an unpulled model is
  never retried; `VectorStore.store()` is never wrapped, because retrying after a failed save
  would index every chunk twice.
- Streaming retries **only until the first token** — after that, restarting would replay output
  the user has already read.
- **Graceful degradation:** when the model is unreachable, retrieval has already succeeded, so
  the user gets the passages that matched instead of an error page.
- Fail-fast on ingestion: a partially embedded document looks complete and silently breaks every
  later answer.

### PR-14b — Observability
- `observability.py`: one logger, two sinks — a per-turn trace shown in the UI, and
  `storage/app.log` rotated at midnight with 7 kept.
- Instrumented the blind spots recorded in earlier PRs: stripped citations, absent citations,
  guardrail rejections, rejected summaries, retrieval counts, stage timings.
- Events are collected in a `ContextVar` holding the **collector**, not a request id — so events
  are never mixed and there is nothing to correlate.
- Logs record counts, verdicts, and identifiers; **never document content or user queries**.
- Introduced a third guardrail contract: the **observer**, which neither rejects nor repairs.

### PR-14a — Configuration
- `config.py`: eleven settings read from environment variables with defaults, validated at
  import so bad configuration fails at startup rather than on the first question.
- Unified four storage paths under one `STORAGE_DIR`. Removed three dead path constants, one of
  which pointed at a filename that never existed.
- `MARKER_MAX` is **derived** from `TOP_K` rather than configured — the two cannot disagree.

### PR-13 — Conversation Memory
- A rolling conversation summary, bounded and citation-free by construction, conditioning
  **both** retrieval and generation.
- Generated by a separate LLM call **after** the stream completes, so it never sits between a
  question and its first token.
- Retrieval query is `summary + question`; retrieving twice and fusing was rejected because RRF
  assumes comparably-competent rankings.
- `text_policy.py` shares the injection check between input and output guardrails — same rule,
  different consequence: reject the user, but *discard* a poisoned summary.
- Summary token cost reported separately as **context upkeep**, never folded into the answer's.

### PR-12 — State Management
- Chat history persisted in session state; answers survive rerun.
- Conversation totals are **derived** from the turn list, never stored.
- `st.rerun()` after each turn — the page is a function of state.
- Indexed documents now listed on load, so corpus facts are no longer trapped in an
  upload-scoped panel.
- Removed the raw embeddings from the ingestion return chain — cached in session state since
  PR-4 and read by nothing since PR-5 (~24 MB per 1000 chunks).

### PR-12a — Streaming
- Tokens stream to the UI, buffered so a citation marker is never split across a flush.
- `MARKER_MAX` derived from the grammar of a marker rather than guessed.
- Typewriter animation in the UI, paced against the model — presentation, kept in a different
  layer from the safety-critical buffer size.
- Recorded the honest trade-off: **streaming trades enforceability for perceived latency.**

## Week 3 — LCEL Refactor

No user-visible change. Everything about how the AI layer is composed.

### PR-11a — Prompt Ownership
- Prompts moved to `prompts.py`. Removed Rule 4 ("under 3 sentences"), a development-time
  constraint that had been truncating every answer in production.

### PR-11c — Citation Verification
- Invented citation markers are stripped deterministically by set membership — no LLM.
- Sanitize, don't reject: a wrong attribution does not make the answer wrong.

### PR-11b — Citations
- Retrieved chunks labelled `<source id="1" file="…">`, with the label↔chunk pairing stored
  explicitly rather than inferred from list position.
- Inline `[n]` markers resolved to filenames in the UI.

### PR-10 — LCEL Composition
- Generation composed as `RunnableParallel | prompt | llm`, deliberately ending at the LLM —
  `StrOutputParser` would discard the token counts and latency the UI reports.
- Prompt split into system (policy) and human (per-request data) messages.
- Established the standing boundary: **a framework may own composition; it must not own
  policy.**
