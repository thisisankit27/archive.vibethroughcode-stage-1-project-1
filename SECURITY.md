# Security

## Scope

This is a **local-first application**. There is no hosted service, no server, no API, and no
account system. It runs on your machine, talks to an [Ollama](https://ollama.com) instance you
control, and writes its state to a local directory. Nothing is transmitted anywhere.

That means most of the usual threat model does not apply — but two things genuinely do.

---

## Reporting a vulnerability

Use GitHub's private reporting: **Security → Report a vulnerability** on this repository. Please
don't open a public issue for anything exploitable.

This is an archived learning project, so treat any response time as best-effort rather than
committed.

---

## What is worth reporting

**Prompt injection that survives a turn.** The conversation summary is generated by the model
from retrieved document content and then injected into every later prompt — so a malicious
document could, in principle, influence answers beyond the request it appeared in. There is a
guardrail for this (`validate_summary` in `data/src/guardrails/output_guardrails.py`, sharing
its rule with the input guardrail via `text_policy.py`), and a bypass of it is a real finding.

**Anything that writes document content to disk outside `storage/`.** The logging layer is
deliberately built to record counts, verdicts, and identifiers but never document text or user
queries. If you find a path where content reaches `storage/app.log` or stdout, that is a bug
worth reporting.

**Path traversal or arbitrary write via an uploaded filename.** Uploads are written to temp
files during ingestion.

---

## What is known and not a vulnerability

These are documented limitations, not undisclosed issues. They are in the README under *Known
limitations* and reasoned through in [`docs/engineering-mindset/`](docs/engineering-mindset/).

- **The injection guardrail is keyword-based**, not a model. It catches obvious attempts and
  will not catch a determined one. It is a speed bump, and the code says so.
- **Rule 6 relies on prompt compliance.** The model is instructed to use conversation history
  only to resolve references and never as a source of facts. A small model does not always
  obey. The symptom is counted and visible in the trace, not prevented.
- **`documents.pkl` is a Python pickle.** Loading a pickle from an untrusted source can execute
  arbitrary code. This file is written by the app itself and read from your own
  `STORAGE_DIR` — do not point `STORAGE_DIR` at a directory somebody else can write to.
- **No authentication.** Streamlit serves to whoever can reach the port. Don't bind it to a
  public interface.
- **Session state is in memory and per-tab.** There is no isolation model beyond that, because
  there is no multi-user design.

---

## Handling your own documents

Everything you upload is chunked, embedded, and persisted to `STORAGE_DIR` (default
`./storage`), including `documents.pkl`, which holds the **full text** of every chunk.

That directory is git-ignored, and it should stay that way. If you fork this repo and index
something sensitive, check `git status` before you push.
